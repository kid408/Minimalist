> **本文讲"为什么这么设计"**：各机制的设计意图、数值为什么这么定、系统之间怎么互相配合。

> 搭 Build、打 Boss，撑到时间结束或先斩 5 只 Boss。

## 一、设计目标

这个游戏想给玩家的体验是 **"每一局的成长路径都不一样"**，具体落到五件事：

| 目标 | 做法 |
|---|---|
| **随机但有方向** | 技能从 72 个池子里随机掉，但玩家可以用商人、祭坛、融合去"修正"运气 |
| **Build 有深度** | 单个技能不是终点，要靠**品质 × 升级 × 联动 × 光环 × 被动**五条线叠加 |
| **操作有分量** | 魔兽式右键操作、按住预览再释放、召唤物框选下令 —— 不只是"站着自动打" |
| **时间压力真实** | 30 分钟倒计时**不因死亡暂停**，威胁等级持续疯长，逼玩家做取舍 |
| **高风险高回报** | 祭坛用永久代价换传说技能；死亡有实质惩罚 |

**刻意不做**的：音频、存档、多英雄、多人。这是有意的范围控制（见 §十二）。

## 二、核心循环

```
进入 6000×4200 迷雾丛林
  ↓
探索杀怪 → 经验 / 金币 / 掉落
  ↓
用 18 个技能槽（6 主动 + 12 融合增益）+ 6 装备槽搭 Build
  ↓
与商人交易（修正运气）· 向祭坛献祭（换传说，付永久代价）
  ↓
指挥最多 8 只召唤物作战
  ↓
威胁等级持续爬升的 30 分钟内，击杀 5 只 Boss、死亡不超过 3 次
  ↓
结算评级 S/A/B/C/F
```

**为什么是"生存目标制"而不是"无尽模式"**：
30 分钟 + Boss 配额给了一个**明确的收束点**，让"这一局搭出来的 Build 到底行不行"有答案。
死亡不暂停是关键设计——它让"少死"本身成为策略，而不是单纯的操作指标。

### 威胁等级：为什么是"疯长曲线"

| 时间 | 等级 | 倍率 |
|---|---|---|
| 0–5 分钟 | 1 | ×1.00 |
| 5–12 分钟 | 2 | ×1.18 |
| 12–20 分钟 | 3 | ×1.36 |
| 20–30 分钟 | 4 | ×1.54 |

设计意图是**前期宽松、后期逼人**：前 5 分钟给玩家从容搭 Build 的时间，
之后每隔一段就跳一档，逼玩家把"攒下的资源"转化成"即时战力"。

两个容易做错、但很重要的细节：

- **等级提升的瞬间，对场上存活敌人也要增量缩放**（不是只影响新生敌人）。
  否则玩家会发现"升级提示弹出来了，但眼前的怪一点没变强"，压力感断裂。
- **Boss 额外 ×1.25**。Boss 是配额目标，必须始终比杂兵更有存在感。

### 死亡与复活：为什么"重生被动"要优先判定

死亡惩罚链的判定顺序是：**先看重生被动，再走常规惩罚**。

- 有 `reincarnate` 充能 → **原地复活 + 60% HP + 3 秒无敌 + 无金币惩罚**（每局 1 次）。
  这让"带重生"成为一个**明确的战略选择**：前期牺牲一个装备槽，换一次免罚。
- 否则 → 损失 30% 金币 + 全技能 5 秒统一冷却 + 回出生点 + 3 秒无敌。
  **三项惩罚分别针对"经济""输出循环""位置"**，让死亡真的很痛，但不至于无法翻盘。

3 秒无敌是必需的——否则复活瞬间会被守在出生点附近的怪立刻再杀一次。

### 结算：评级在鼓励什么

```
分数 = 用时分钟 − 死亡×12 + (0 死亡 ? +25 : 0) + (剩余 HP > 50% ? +8 : 0)
S ≥ 35 / A ≥ 22 / B ≥ 10 / C 其它 / 失败 = F
```

注意 `用时分钟` 是**加分项**：快速通关（提前打完 5 Boss）反而分数低。
这是刻意的设计——**评级奖励"打得稳"而不是"打得快"**，
与"30 分钟生存"这个核心目标保持一致。

## 三、操作与手感

| 输入 | 动作 |
|---|---|
| W/A/S/D | 键盘移动（按下会取消点击移动） |
| 鼠标右键 | 点击移动；点中敌人 → 锁定为**集火目标**（超出 600px 自动解除）；在选取/引导态下 = 取消 |
| 鼠标左键 | 框选/点选召唤物；单体技能确认目标 |
| 1–6 | 技能键 |
| Space | 交互（优先级：商人 > 祭坛 > 拾取） |
| J | 免费召唤（受 8 上限约束） |
| T | 属性面板 |
| Esc | 取消 |

**"按住预览、松开释放"是核心手感设计。**
按住时显示范围遮罩，让玩家先确认再决定；松开才真正消耗能量并进入冷却。
这比"按下即释放"多了一次确认机会，让范围技能用起来更从容，
也让"取消施法"成为可能（松开前移出范围或直接右键）。

**预览遮罩按几何形态区分颜色**是有意的：玩家不用读文字就能知道"这个技能打哪个范围"。
冷却中或能量不足时**只飘字、不显示遮罩**——避免玩家以为还能放。

## 四、英雄与属性成长

### 英雄：极锋（vanguard）

| 项 | 值 | 设计意图 |
|---|---|---|
| 定位 | 近战压制 · 均衡型 | 唯一的英雄，必须适配各种 Build |
| 移速 | 235 | 足够躲开大部分弹体，但不至于无脑拉扯 |
| 普攻 | 24 伤害 / 0.46s 间隔 / 72 射程 | 近战定位：射程短，逼玩家贴近 |
| 最大 HP | `100 + 体质×8`（初始 **180**） | 体质收益线性且直观 |
| 最大能量 | **100** | 技能的主要约束资源 |
| 基础回能 | 5.0/s | 约 20 秒回满，让技能有节奏感 |

### 五维属性（初始 5/5/5/10/0）

| 属性 | 收益 | 为什么这么定 |
|---|---|---|
| 力量 str | 近战伤害 +3%/点（普攻 + `aoe_self` 技能） | 让"贴脸 AOE"流有专属加成，与技能流区分 |
| 敏捷 agi | 移速 +2%/点、攻速 +3%/点 | 同时给生存与输出，是"手感型"加点 |
| 智力 int | 技能伤害 +3%/点、回能 +0.5/s 每点 | 技能流的核心，回能让"高频放技能"成立 |
| 体质 vit | 最大 HP +8/点 | 线性、可预期 |
| 幸运 luk | 掉落品质偏移 +2%/点 | 给"我要赌一把"的玩家一条正反馈 |

**属性总值的三个来源**：基础值 + 装备加成 + 自由加点（光环/被动再叠加一层）。
UI 显示与逻辑计算**必须共用同一份公式**（属性 tooltip 自己算一遍是最常见的数值漂移来源）。

**技能点**：开局 6 点，每升 1 级 +1；可在属性面板重置并**全额返还**。
设计意图是**允许试错**——玩家不该因为早期加点失误而被锁死。

### 生存资源三件套

| 资源 | 规则 | 设计意图 |
|---|---|---|
| 护盾 | 限时吸收，**取最大值不叠加** | 防止叠盾变成"无敌"；让玩家在"续盾"和"开新的"之间取舍 |
| 临时增益 | `buff_stat` 施加，限时**取最强倍率** | 同类增益不叠乘，避免滚雪球失控 |
| 反伤 | 限时，按所受伤害比例反弹 | 给"站着挨打"一种反制价值 |

## 五、技能系统

这是整个游戏的核心。设计上有两条主线：**施法方式决定手感，效果原语决定内容**。

### 5.1 六种施法方式（"怎么放"）

| 方式 | 行为 | 手感定位 |
|---|---|---|
| `instant` 瞬发 | 按住预览、松开结算 | 最流畅，适合高频输出 |
| `point` 点地 | 在鼠标落点结算（施法距离 600） | 需要预判，适合 AOE |
| `unit_target` 单体 | 进入选取态，点击目标确认 | 精确点杀，可右键取消 |
| `channel` 引导 | 站桩持续结算（每 `tick_interval` 一次，共 `duration` 秒） | 高风险高回报：位移 >14px 或再按技能键即打断 |
| `aura` 光环 | **入槽即常驻生效**，不可主动释放 | 零操作的被动收益 |
| `toggle` 开关 | 按键切换；开启期间**每秒耗能**，能量尽或换槽自动关 | 持续输出 vs 持续耗能的取舍 |

**引导的"14px 打断容差"** 是个关键手感参数：
完全不许动会太苛刻，容差太大又失去"站桩"的意义。14px 允许微调站位，但一走就断。

### 5.2 八种几何形态（"打哪里"）

`self_ring` 自身环 / `circle` 落点圆 / `line` 直线突进 / `cone` 扇形（45°） /
`projectile` 弹体 / `target` 单体 / `summon` 召唤 / `none` 纯增益。

目标侧 `target_side`：`enemy` / `ally` / `self` / `both` / `ground`。

### 5.3 subtype：由形态派生的"技能家族"

`subtype` 不占数据表列，**加载时由 `shape` 自动派生**：

| shape | subtype |
|---|---|
| `self_ring` / `cone` | `aoe_self` |
| `circle` | `aoe_ground` |
| `line` | `dash` |
| `projectile` | `projectile` |
| `target` | `single` |
| `summon` | `summon` |
| `none` | `buff` |

这么设计是为了让**联动、装备加成这类"跨技能规则"有统一的分组依据**，
而不用在每个技能上手工打标、担心漏标或标错。

### 5.4 品质与升级：两条独立的成长线

| 机制 | 效果 | 设计意图 |
|---|---|---|
| **品质** | 只乘 `damage`：white 1.0 / blue 1.25 / purple 1.6 / orange **1.0** / legendary 2.1 | 品质是"稀有度"，只放大数值，不改机制 |
| **升级** | 拾取同名技能：`level+1`、`damage ×1.15`、品质逐级提升 | 让"捡到重复技能"不再是负面体验 |

两条线**叠乘**：一个 legendary Lv.5 的技能 = `基础 × 2.1 × 1.15⁴`，成长非常可观。
这给了玩家"专注养一个技能"的正反馈路径。

> `orange` 倍率是 **1.0**，与其它品质不成序列 —— 这是刻意保留的设定，不要"修正"。

### 5.5 联动（Synergy）：鼓励"选同类"

同 `subtype` 的**主动**技能在槽中达到 **2 个**即触发：

| subtype | 加成 |
|---|---|
| `aoe_self` | 冷却 ×0.8 |
| `aoe_ground` | 半径 ×1.2 |
| `dash` | 突进距离 ×1.3 |
| `projectile` | 弹体速度 ×1.4 |

**关键设计**：联动改的是**冷却/半径/距离/弹速**，**不进入伤害链路**。
这样联动是"手感与覆盖面的提升"，而不是"再加一层乘法"——
避免 Build 强度陷入纯数值膨胀，让选择更有策略性。

### 5.6 融合（augment）：一个技能的两种用法

每个主动技能槽配 **2 个增益槽**。增益技能**不提供自己的伤害与半径**，
只把 `effects` 注入主技能（数值键按 `decay=0.5` 累加，bool 键置真）。

设计意图：**让"用不上的技能"也有价值**。
抽到一个品质差、数值低的技能，仍可以塞进增益槽当"效果插件"用。
`decay=0.5` 是刻意打折——融合应该是"锦上添花"，不能盖过主技能本身。

增益技能若填了 `augment_effects` 就用它，**该列为空则回退用其自身的 `effects`**。

### 5.7 72 个技能的构成

`instant 33 / point 7 / unit_target 10 / channel 5 / aura 13 / toggle 4`。

结构上刻意做了**成对设计**：大量技能存在"低品质基础版 + 高品质强化版"
（如 `ice_nova` ↔ `frost_nova`、`warcry` ↔ `battle_trance`），
让玩家能明显感知到"我抽到了上位版本"，也让升级路径更有层次。

按学派分为：physical / fire / ice / lightning / nature / shadow / holy / arcane / summon / lifesteal。
学派本身不提供加成，作用是**视觉区分与玩家的心智归类**。

（完整的 72 个技能逐条数值见建造规格书 §4.7。）

## 六、光环 / 被动 / 开关的运行时体系

| 类型 | 生效方式 | 设计意图 |
|---|---|---|
| **光环** | 入槽即常驻，`aura_value` 按等级 `base ×(1+(level−1)×0.3)` 成长；同 `aura_stat` 叠乘 | 零操作成本，"装上去就一直在" |
| **被动** | 入槽即常驻 | 同上 |
| **开关** | 主动开启，每秒耗能，能量耗尽自动关 | 需要主动管理的持续战力，用能量换输出 |

光环有个容易做错的点：**装槽/卸下/换槽/拾取升级后必须立即重算**。
推荐用"脏标记 + 惰性重算"，避免每帧全量扫描。

13 个光环覆盖了力量、速度、生命、智慧、回血、回能、暴击、减速、荆棘、吸血、减伤等方向，
**互相之间可叠乘**——这是后期 Build 强度的主要来源之一。

## 七、召唤物（轻 RTS）

| 规则 | 值 | 设计意图 |
|---|---|---|
| 上限 | 8 只 | 够形成一支小队，又不至于变成纯召唤流 |
| 操作 | 左键框选（绿框）/ 点选，右键下令移动或攻击 | 给魔兽玩家熟悉的操作感 |
| 免费召唤 | J 键（仍受上限约束） | 保证"没抽到召唤技能"的玩家也能体验 RTS 部分 |
| 属性成长 | 蛇杖系→智、骷髅系→力、其它→敏（未配置回退 `default`） | **让召唤流与属性加点产生联动**，而不是固定数值 |
| **伤害豁免** | **召唤物免疫一切伤害**，只因寿命到期消失 | 刻意设定：避免"召唤物被 AOE 清场"的挫败感 |

**"随属性成长"是召唤物系统的灵魂**——它让"智力和力量"这两个平时偏辅助的属性，
对召唤流变成核心属性，从而产生一条独立的 Build 路线。

## 八、装备（11 件）

10 件装备 + 恢复石。价格统一为 **50 金购买**，但**卖价按品质分档**（15/25/40），
形成"买进来贵、卖出去亏"的损耗，避免玩家刷商人套利。

| 装备 | 定位 | 特殊机制 |
|---|---|---|
| 铁卫胸甲 / 皮靴 / 布袍 | 白色入门 | 纯属性 + 布袍额外回能 |
| 猎弓 / 疾行靴 | 攻速 / 移速 | 手感向 |
| 专注吊坠 | **最大能量 ×0.7**，换回能 +1 | **有代价的取舍**：能量池变小但回得更快 |
| 魔法盾护符 | 能量 >50% 时用能量抵扣伤害 | 让"保持高能量"变成一种防御策略 |
| 虹吸戒指 | 吸血 15% | 续航 |
| 毁灭者印记 | `aoe_self`/`aoe_ground` 技能伤害 ×1.3 | **流派限定加成**，强化 AOE 流 |
| 过载核心 | 连杀 5 只 → 回能翻倍 3 秒 | 奖励"连续作战"，鼓励主动清场 |
| 恢复石 | 固定占 E1，点击使用 | 保底续航，15 次击杀充满 |

**恢复石固定在装备槽第 1 格、不可拖动、点击使用**是刻意设计：
它是保底机制，不该被玩家"换掉"或"误丢"。

## 九、掉落、商人、祭坛：三种修正运气的手段

纯随机掉落会让局与局之间差异过大。所以设计了三条"修正途径"：

| 途径 | 机制 | 修正什么 |
|---|---|---|
| **商人** | 花金币买装备、升级技能品质（30/60/120）、删除、出售 | 用**金币**换确定性 |
| **祭坛** | 付出**永久代价**换一个 legendary 技能 | 用**长期代价**换爆发力 |
| **幸运属性** | 掉落品质偏移 `luk × 2%` | 用**加点**提高随机质量 |

### 祭坛的代价设计

代价是**永久**且**直接削核心数值**的（最大生命 / 最大能量 / 移速 / 损失 40% 金币）。
这是全游戏最激进的取舍：传说技能很强，但你会带着debuff打完全局。
每局场上 **2 座**祭坛，玩家可以只选一座、也可以两座都换。

商人的**技能书不可出售（置灰）**是刻意设计：
防止玩家把不要的技能全卖了换钱，破坏经济。

## 十、世界与敌人

| 项 | 值 | 设计意图 |
|---|---|---|
| 地图 | 6000×4200，迷雾半径 700 | 大到需要探索，小到 30 分钟能跑遍 |
| 相机 zoom | 0.9 | 只看局部，保留探索感 |
| 初始刷怪 | 普通 80 / 精英 12 / Boss 1 | 密度足够"随时有怪打" |
| 敌人不堆叠 | 空间网格分离（格 120，最小间距 34） | 避免怪挤成一坨，保证 AOE 与走位都有意义 |

### 敌人三档

| 档 | HP | 移速 | 伤害 | 经验 | 掉落率 | 贴图缩放 |
|---|---|---|---|---|---|---|
| 普通 | 50 | 195 | 10 | 3 | 0.15 | 0.55 |
| 精英 | 150 | 351 | 10.5 | 15 | 0.5 | 0.55 |
| Boss | 600 | 682.5 | 6 | 60 | 1.0 | **0.7** |

注意 **Boss 的单次伤害反而比杂兵低**（6 vs 10）——
Boss 的威胁来自**高血量与高移速**（682.5，远快于玩家 235），
设计上是"追着你打、很难甩掉、需要长时间输出"，而不是"一巴掌拍死你"。

### 敌人 AI：领地制

四状态：`idle`（出生点游走）→ `chase`（追击）→ `attack`（攻击）→ `return_home`（回巢）。

**领地制是核心设计**：怪只在自己出生点附近活动，玩家追出 600px 它就会回巢。
这让**大地图探索是安全的**（不会被全图的怪追杀），
同时让"清一片区域"成为有效的短期目标。

回巢途中玩家进入 **510px**（比追击距离 600 小）会重新追击 ——
这个**滞后区间**是为了避免敌人在边界反复横跳。

四种行为分支（近战 / 远程 / 自爆 / 冲锋）按随机阈值 `0.6 / 0.8 / 0.95` 决定，
让同一片区域里的怪也有行为差异。

## 十一、战斗手感与反馈

| 反馈 | 规格 | 为什么 |
|---|---|---|
| 伤害飘字 | 普通 16 号黄 / 暴击 21 号橙，上飘淡出 | 暴击必须**一眼可辨**（字号 + 颜色双重区分） |
| 预览遮罩 | 按形态分色 + 220px 瞄准线 | 让玩家"看得见"技能范围 |
| 受击闪白 | 命中瞬间变亮再回正 | 即时命中确认 |
| 无敌期 | 玩家半透明蓝色调制 | 明确传达"现在打不到我" |
| 地面持续区域 | 橙红径向渐变 | 危险区域的视觉警告 |
| 召唤物选框 | 绿色选框 | 与敌人、玩家区分 |
| 迷雾 | 深灰蓝，半径 700 | 制造未知与探索压力 |

**伤害管线的顺序是玩法的一部分，不能调换**：

```
闪避 → 受伤加深(破甲/受伤加深) → 护盾 → 魔法盾护符(能量>50%) →
减伤(上限90%) → 扣HP → 吸血 → 反伤 → 击退
```

几个关键设计点：

- **闪避在最前面**：闪避成功就不该消耗护盾。
- **减伤上限 90%**：避免"堆减伤 = 无敌"，给极限 Build 一个天花板。
- **反伤不连锁**：否则两个反伤单位互相弹会无限循环。
- **无敌期在扣血前拦截**：复活无敌必须真的无敌。

## 十二、系统之间怎么咬合（整体设计）

这个游戏的所有系统最终都指向**同一个目标：让每一局的 Build 不同**。

```
        掉落（随机）+ 商人（金币换确定）+ 祭坛（代价换爆发）
                            ↓
              18 个技能槽 + 6 装备槽（容器）
                            ↓
    品质 × 升级 × 联动 × 融合 × 光环被动  （五条成长线，互相叠乘）
                            ↓
          属性加点（力/敏/智/体/运 → 决定成长方向）
                            ↓
              威胁等级疯长（外部压力）→ 30 分钟生存目标
```

**五条成长线互相叠乘**是强度的主要来源：单看每一条都不夸张，
但叠在一起能让后期 Build 产生质变——这正是"类幸存者"品类的爽点。

### 刻意保留的设计（不要"顺手修正"）

以下看起来像 bug，其实是刻意设定：

1. **召唤物免疫伤害** —— 避免召唤物被 AOE 清场的挫败感。
2. **`banish` / `prison` 等原语可无技能使用** —— 效果原语库的能力预留，方便后续加技能。
3. **无音频、无存档、无多英雄** —— 有意的范围控制。
4. **`orange` 品质倍率 = 1.0** —— 与其它品质不成序列。
5. **多个技能共用同一个图标** —— 历史数据状态，保持原样。
6. **`skill/04` 无技能引用但需可生成** —— 保持图标 key 连续。
