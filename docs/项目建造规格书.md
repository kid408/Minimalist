## 1. 项目概述与运行环境

### 1.1 游戏是什么

2D 俯视角、单英雄、类《幸存者》的 ARPG，单局固定 30 分钟。

**核心循环**：

```
进入 6000×4200 的迷雾丛林
  → 探索杀怪，攒经验 / 金币 / 掉落
  → 用 18 个技能槽（6 主动 + 12 融合增益）和 6 装备槽搭建 Build
    （品质 × 升级 × 联动 × 光环 × 被动 五维成长）
  → 与商人交易、向祭坛献祭换传说技能
  → 指挥最多 8 只随属性成长的召唤物作战
  → 在威胁等级持续增长的 30 分钟内击杀 5 只 Boss、死亡不超过 3 次 → 胜利
  → 结算获取 S/A/B/C/F 评级
```

**胜负判定**：

- **胜利**：击杀 Boss **5 只**，且死亡数 ≤ 3 → 立即胜利。
- **失败**：**第 4 次死亡**（死亡数 > 3）→ 立即失败。
- **时间到**（1800 秒）：死亡数 ≤ 3 判胜，否则判负。
- 倒计时**不因死亡而暂停**。

### 1.2 运行环境

| 项 | 要求 |
|---|---|
| 引擎 | Godot **4.x**（4.4+）；`config/features` 按实际引擎版本填写 |
| 语言 | 纯 GDScript；**不使用 C#、不使用任何第三方插件/addons** |
| 渲染 | Forward+ |
| 平台 | 主验证平台 Windows（`rendering_device/driver.windows="d3d12"`、`3d/physics_engine="Jolt Physics"`） |
| 窗口 | 1440×810，`window/stretch/mode="canvas_items"` |
| 主场景 | 主菜单 |
| 缩进 | 所有 `.gd` 使用 **Tab** 缩进（Godot 不允许 Tab/空格混用） |
| 编码 | 全部 UTF-8 无 BOM |

### 1.3 输入映射

| Action | 默认键 |
|---|---|
| `move_up` / `move_down` / `move_left` / `move_right` | W / S / A / D |
| `skill_1` … `skill_6` | 1 … 6 |
| `interact` | Space |
| `free_summon` | J |
| `toggle_attribute_panel` | T |
| `ui_cancel` | Esc |

鼠标：**左键** = 框选/点选召唤物、UI 交互；**右键** = 点击移动、对敌集火、取消选取态、槽位快捷丢弃。

> 除了写进 `project.godot`，还要在运行时做一次**输入映射兜底注册**：
> 启动时检查上述 action 是否存在，缺失则用代码补建。这样即使配置损坏，游戏仍可操作。

### 1.4 有意不包含

**不要**添加以下内容（即使你认为"应该有"）：

- 音频（无音效、无 BGM）
- 存档（退出即结束，不持久化）
- 多英雄（只上线 1 个英雄）
- 多人、本地化、成就系统

### 2.2 模块职责（边界必须遵守）

| 模块 | 只负责 | **不得**负责 |
|---|---|---|
| `game.gd` | 建状态 → 建依赖 → 建系统并注入 → 驱动帧循环 | 存游戏状态、写数值、创建 UI 控件 |
| `GameState` | 持有全部可变运行时状态 | 派生计算（走 `Formula`/`StatService`） |
| `player_controller` | 输入 → 移动意图 / 点击移动 / 集火 / 相机 | 伤害结算 |
| `skill_system` | cast_mode 分发、CD 与能量、预览、选取态、引导、开关 | 具体几何结算（交给 combat） |
| `combat_system` | 普攻、按 shape 结算、预览信息计算 | 直接修改其它系统状态 |
| `damage_pipeline` | 按固定顺序执行伤害步骤 | 判断死亡（由 `unit.die` 负责） |
| `world_system` | 刷怪/重生/掉落/商人/祭坛/空间网格 | 玩家死亡处理（属 survival） |
| `inventory_system` | 槽位读写、拖放规则、拾取、装备生效 | UI 渲染 |
| `aura_system` | 光环/被动的常驻加成聚合（脏标记重算） | — |
| `survival_system` | 倒计时、威胁等级、胜负、结算、死亡惩罚链 | — |
| `ui/hud.gd` | 订阅事件 → 更新控件显隐与文本 | 游戏逻辑、直接调用系统方法 |

### 2.3 架构约束（**建完逐条自查，全部满足才算合格**）

**依赖方向单向**：

```
core  ←  data  ←  effects / actors  ←  systems  ←  game  →  ui
```

- `core` 不依赖任何上层；`data` 只依赖 `core`；`systems` 依赖 `core + data`。
- **没有任何脚本依赖 `game.gd`**（它是顶层装配器）。
- **系统之间不互相持有引用**：要通知 → 发 `Events` 信号；要取值 → 从 `SystemContext` 读 `state` / `stats`。

**9 条红线**：

| # | 红线 | 怎么验 |
|---|---|---|
| 1 | `game.gd` ≤ 200 行，不含任何平衡数值、不含任何控件 `new()` | 数行数 + 人工看 |
| 2 | 无脚本 `preload`/引用 `game.gd` | 全文搜索 `game.gd`，除主场景配置外应为 0 |
| 3 | 单个 `.gd` ≤ 400 行 | 遍历统计，最大值 ≤ 400 |
| 4 | 各系统文件不出现其它系统的类名，也不出现 `get_node("../Xxx")` | 搜索确认 |
| 5 | `ui/hud.gd` 中 `.new()` ≤ 5 次（仅飘字等动态元素） | 计数 |
| 6 | 平衡数值字面量只在 `tunables.gd` / TSV / `defs` 出现（UI 布局像素除外） | 搜索 `0.xx` / 两位以上整数 |
| 7 | `Formula` 是派生公式唯一实现，无第二处复制 | 搜索 `* 0.03`、`vit * 8` 等片段 |
| 8 | 项目不引用任何图片文件 | 全文搜索 `res://assets` 应为 0 |
| 9 | 新增一个效果原语 = 新增 1 个文件（+注册表 1 行），不改既有文件 | 实际演练一次 |

### 2.5 槽位统一寻址

用值对象 `SlotRef{kind, index, aug_index}`，`kind ∈ {SKILL, AUGMENT, WAREHOUSE, EQUIPMENT, GROUND}`。

**拖放只有一条规则**：`move(from: SlotRef, to: SlotRef)`，覆盖全部 7 种组合（§7.2）。
读槽位用 `GameState.slot_get(ref)`；**写槽位的唯一入口是 `InventorySystem`**。

## 3. 英雄、属性与成长

### 3.1 英雄（只有 1 个）

| id | 名称 | 定位 | 移速 | 普攻伤害 | 普攻间隔 | 普攻射程 |
|---|---|---|---|---|---|---|
| `vanguard` | 极锋 | 近战压制 · 均衡型 | **235** | **24** | **0.46s** | **72** |

| 项 | 值 |
|---|---|
| 初始属性 | 力 **5** / 敏 **5** / 智 **5** / 体 **10** / 运 **0** |
| 初始技能点 | **6** |
| 最大 HP | `100 + 体质×8`（初始 = 180） |
| **最大能量** | **100**（固定；专注吊坠会将其 ×0.7） |
| 基础回能 | **5.0 /s**（受智力与装备加成） |

数据结构支持多英雄，但**只上线这一个**。

### 3.2 属性收益（唯一真源：`Formula`）

| 属性 | 收益 |
|---|---|
| 力量 str | 近战伤害 +3%/点（作用于**普攻**与 `aoe_self` 类技能） |
| 敏捷 agi | 移速 +2%/点、攻速 +3%/点 |
| 智力 int | 法术伤害 +3%/点（作用于**技能伤害**）、回能 +0.5/s 每点 |
| 体质 vit | 最大 HP +8/点 |
| 幸运 luk | 掉落品质偏移 +2%/点 |

```
max_hp(vit)         = 100 + vit * 8
melee_mult(str)     = 1 + str * 0.03        # 普攻、aoe_self 技能
spell_mult(int)     = 1 + int * 0.03        # 其它技能伤害
attack_speed_mult   = (1 + agi * 0.03) * temp_buff(attack_speed_pct)
move_speed_mult     = (1 + agi * 0.02) * temp_buff(move_speed_pct)
energy_regen(int)   = 5 + int * 0.5 + mana_regen_bonus
drop_quality(luk)   = luk * 0.02
xp_required(level)  = 10 + level * 8
```

**属性面板 tooltip 必须调用 `Formula`**，不得自己再算一遍（这是最常见的数值漂移来源）。

### 3.3 成长

- 击杀经验：普通 **3** / 精英 **15** / Boss **60**。
- 升级需求：`10 + 等级 × 8`；**无等级上限**。
- 每次升级：**技能点 +1**。
- 属性面板：加点立即生效；**点数耗尽时加点被拦截**；**重置返还全部已用点数并回滚属性**。

## 4. 技能系统

### 4.1 六种施法方式（cast_mode）

| cast_mode | 行为 |
|---|---|
| `instant` | **按住**技能键 → 显示预览遮罩；**松开** → 立即结算 |
| `point` | 按住 → 落点预览；松开 → 在落点结算。**施法距离 600**，超出不可释放 |
| `unit_target` | 按下 → 进入选取态（准星跟随鼠标）；点击目标或再按技能键确认；**右键取消**；超距拦截 |
| `channel` | 站桩持续结算（每 `tick_interval` 触发一次）；**位移超过 14px** 或**再按该技能键** → 打断 |
| `aura` | **放入槽位即常驻生效**；按键不释放，提示"装备即生效"，HUD 显示"被动"标签 |
| `toggle` | 按键切换开关；开启期间**每秒**消耗 `energy_cost` 能量；能量耗尽或换槽 → 自动关闭 |

### 4.2 八种形态（shape）

| shape | 几何 | 说明 |
|---|---|---|
| `self_ring` | 以自身为中心的圆环区域 | 用 radius |
| `circle` | 以落点为中心的圆形区域 | 用 radius |
| `line` | 沿方向突进 | 命中沿途敌人，终点为落点，受地图边界 clamp |
| `cone` | 以自身为顶点的扇形 | radius 为长度，**张角 45°** |
| `projectile` | 沿方向飞行的弹体 | 命中首个敌人后结算（除非有 `pierce`/`chain`） |
| `target` | 单体 | 直接作用于选中目标 |
| `summon` | 召唤 | 在施法者附近生成召唤物 |
| `none` | 无几何 | 纯增益（护盾/治疗/自身 buff） |

### 4.3 subtype（**由 shape 派生，不占表列**）

联动（§4.4）与毁灭者印记（§6.2）都依赖 `subtype`。加载技能时按下表**自动派生**：

| shape | 派生的 subtype |
|---|---|
| `self_ring`、`cone` | `aoe_self` |
| `circle` | `aoe_ground` |
| `line` | `dash` |
| `projectile` | `projectile` |
| `target` | `single` |
| `summon` | `summon` |
| `none` | `buff` |

### 4.4 品质与升级

**品质倍率（只乘 `damage`，在施法时计算）**：

| quality | 倍率 |
|---|---|
| white | 1.0 |
| blue | 1.25 |
| purple | 1.6 |
| orange | **1.0** |
| legendary | 2.1 |

> `orange` 的倍率**就是 1.0**，与其它品质不成序列。这是刻意设定（§17），不要"修正"。

**升级**（拾取同名技能 → 直接吃升级，不入仓库）：

- `level += 1`
- `damage *= 1.15`（与品质倍率**叠乘**）
- 品质逐级提升：white → blue → purple → legendary（到 legendary 后不再变）
- **不改动** radius / duration / cooldown / energy_cost / effects
- **无等级上限、无次数上限**

### 4.5 联动（Synergy）

- **触发条件**：主动技能槽中，`subtype` 相同的 **`cast_type=active`** 技能数量 **≥ 2**。与 school、quality 无关。
- **效果**：

| subtype | 加成 |
|---|---|
| `aoe_self` | 冷却 × 0.8 |
| `aoe_ground` | 半径 × 1.2 |
| `dash` | 突进距离 × 1.3 |
| `projectile` | 弹体速度 × 1.4 |

- **联动只改冷却/半径/距离/弹速，不进入伤害链路。**
- **显示**：HUD 消息行追加 `[联动: 环绕×2 …]` 形式的提示。

### 4.6 融合（augment）

- 每个主动技能槽配 **2 个增益槽**。
- **取用哪份效果**：增益技能若填了 `augment_effects` 列则用它；**该列为空则用该技能自身的 `effects`**。
- **合并规则**（施法时把增益效果注入主技能的效果字典）：
  - 数值键：**累加** → `当前值 + 增益值 × decay`，`decay` 默认 **0.5**
  - bool 键：任一增益为 `true` 即置 `true`
- 增益技能**自身的 damage / radius 不参与计算**，只注入 effects。
- 融合后**品质与等级取主技能**。
- 释放时主技能与增益效果**同时结算**。

## 6. 战斗与伤害管线

### 6.1 普攻

- 自动索敌：射程 **72** 内最近的敌人；玩家指定集火目标时优先攻击该目标。
- 间隔 **0.46s**，受攻速加成影响。

**普攻伤害链路**（严格按序）：

```
base = 24
× melee_mult(str)                     # 1 + str*0.03
× (1 + equipment.damage_pct)
× (1 + aura.damage_pct)
× (1 + temp_buff[damage_pct])
→ 暴击判定（crit_chance / crit_mult，默认暴击倍率 2.0）
→ 分裂判定（若有 cleave，对周围敌人追加 cleave 比例的溅射伤害）
→ 进入伤害管线
```

### 6.2 技能伤害链路（严格按序）

```
base = 技能 damage
① 若 energy_dmg_ratio：base 改写为 当前能量 × ratio
② 若 consume_all_energy：base × (1 + 当前能量 × 每点加成)，随后能量清零
③ 若装备 destroyer_mark 且 subtype ∈ {aoe_self, aoe_ground}：× 1.3
④ × 品质倍率（white 1.0 / blue 1.25 / purple 1.6 / orange 1.0 / legendary 2.1）
⑤ × 等级倍率 1.15^(level−1)
⑥ × 属性倍率：subtype = aoe_self 时用 melee_mult(str)，其它用 spell_mult(int)
⑦ × (1 + equipment.damage_pct)
⑧ × (1 + aura.damage_pct)
⑨ × (1 + temp_buff[damage_pct])
⑩ 形态修正：projectile_mult 多重 / chain 每跳 ×0.6 / 范围中心区 × core_multiplier
          / 地面持续区 × ground_dps_mult
⑪ 暴击判定
→ 进入伤害管线
```

> 联动（§4.5）改的是**冷却/半径/突进距离/弹速**，**不出现在本链路里**。

### 6.2.1 引导 / 持续 / 地面的伤害口径（必须统一）

这类技能有多个"每次结算多少"的口径，容易倍数级出错。**统一规定**：

| 类型 | 每次结算量 | 总伤害 |
|---|---|---|
| **引导 channel** | 每 `tick_interval` 结算一次**完整 damage** | `damage × (duration / tick_interval)` |
| **持续伤害 dot** | 参数是**每秒**伤害 | `dps × duration` |
| **地面持续区域** | 每 0.6s 结算一次 `伤害 × ground_dps_mult` | `伤害 × ground_dps_mult × (ground_secs / 0.6)` |

举例：`lightning_bolt_channel` 的 `damage=50, duration=1.5, tick_interval=0.3`
→ 结算 **5 次**，每次 50，**总计 250**（**不是**总共 50）。

### 6.3 伤害管线（**顺序固定，不可调换**）

| 序 | 步骤 | 规则 |
|---|---|---|
| 0 | **闪避判定** | 命中 `evasion` 则整次伤害无效，直接结束 |
| 1 | **目标受伤加深** | 乘 `armor_break` 倍率与 `damage_taken` 加成 |
| 2 | **护盾吸收** | 先扣护盾；护盾**取最大值，不叠加** |
| 3 | **魔法盾护符** | 装备 `mana_ward` 且**能量 > 50%** 时，用能量抵扣剩余伤害 |
| 4 | **伤害减免** | `damage_reduce`，**上限 90%**（超出按 90% 计） |
| 5 | **扣 HP** | **无敌期内不结算伤害**；HP 归零 → 触发死亡 |
| 6 | **吸血** | 按实际扣血量 × `lifesteal` 回复攻击者 HP |
| 7 | **反伤反弹** | 按 `reflect` 比例反弹给攻击者；**反伤不再触发反伤** |
| 8 | **击退** | 按 `knockback` 距离沿"攻击者→目标"方向推开 |

**实现要求**：管线是可插拔步骤的有序列表（每步一个类，按优先级排序执行），
新增一条伤害规则 = 新增一个步骤类并注册，**不改动管线本体与既有步骤**。

## 10. 生存目标、死亡与结算

### 10.1 目标

- 单局 **1800 秒**倒计时，**死亡不暂停**。
- 击杀 Boss **5** 只且死亡 ≤ 3 → 立即胜利。
- 死亡 **> 3**（第 4 次）→ 立即失败。
- 时间到：死亡 ≤ 3 判胜，否则判负。

### 10.2 死亡惩罚链（顺序固定）

1. **优先判定重生被动**：若持有带 `reincarnate` 能力的装备且尚有充能 →
   **原地复活 + 60% HP + 3 秒无敌 + 无金币惩罚**，消耗充能（**每局 1 次**）。
2. 否则走常规惩罚（**死亡数 +1**）：
   - 损失 **30%** 金币
   - **所有技能**进入 **5 秒**统一冷却
   - 传送回出生点（地图中心 + `(0, 180)`）
   - **3 秒无敌**：无敌期内敌人攻击**不结算伤害**，玩家显示半透明蓝色调制
   - HP 恢复至满
   - HUD 提示 `你阵亡了！损失 N 金币（死亡 x / 3）`

### 10.3 结算

```
分数 = 用时分钟 − 死亡×12 + (0 死亡 ? 25 : 0) + (剩余HP > 50% ? 8 : 0)
评级 = S(≥35) / A(≥22) / B(≥10) / C(其它)；失败 = F
```

结算面板显示：**评级、击杀数、Boss 进度、死亡数、用时、等级、金币、剩余 HP%**。
`R` 键重开一局。结算面板在游戏暂停后**仍可交互**。

**单位贴图（150×150）**：中心 `(75, 78)`，半径 `42%`：

- 圆内填 `主色.darkened(0.35)`，内圈（`d < r*0.55`）填 `主色.lightened(0.18)`
- 顶部画朝向三角：`y < -r*0.35 且 abs(x) < (abs(y) - r*0.35) * 0.8` → `主色.lightened(0.55)`
- **敌人三档主色固定**（不取哈希）：`unit/enemy_normal` 用色表索引 0（蓝）、
  `unit/enemy_elite` 用索引 4（金）、`unit/enemy_boss` 用 `Color(0.75, 0.25, 0.30)`（暗红）
- `unit/player` 用索引 2（绿）；`unit/summon` 用索引 2 且整体半径缩小到 `30%`

**弹体（96×96）**：中心半径 `34%` 的径向渐变，
中心 `Color(1.0, 0.85, 0.45)`、边缘透明（alpha 由内向外 1 → 0）。

**地图瓦片（994×460）**：底色 `Color(0.13, 0.19, 0.15)`（暗绿），
每像素叠加确定性噪声：

```
n = sin(x*0.031) * cos(y*0.047) * 0.5
  + sin((x+y)*0.011) * 0.3
  + sin(x*0.11 + y*0.07) * 0.12
color = 底色.lightened(n * 0.09)
```

再叠加网格线：`x % 64 == 0 或 y % 64 == 0` 的像素 `lightened(0.05)`。

### 12.4.1 遮罩随动规则（决定手感，必须遵守）

| 形态 | 遮罩跟随什么 | 说明 |
|---|---|---|
| `self_ring` | **锁在玩家身上** | 不跟鼠标，玩家移动时遮罩跟着走 |
| `cone` | **锁在玩家身上，朝向鼠标** | 扇形开口方向 = 玩家 → 鼠标 |
| `circle` | **跟随鼠标落点** | 超距时见下 |
| `line` | 玩家 → 鼠标的**方向线** | 长度取 `突进距离` 与 `玩家→鼠标距离` 的**较小值** |
| `projectile` | 玩家 → 鼠标的**方向线 + 220px 瞄准线** | 同 `line` 的长度规则 |
| `target` | **无遮罩** | 改为：鼠标下方的敌人高亮描边（红色） |

**超距处理**（`circle` / `line` / `projectile` 当 `玩家→鼠标距离 > 施法距离(600)`）：

- 遮罩**继续显示**，但位置被 clamp 到以玩家为圆心、半径 600 的圆周上；
- 遮罩颜色**叠一层红色调制**（`Color(1, 0.4, 0.4, 1)` 作为 `modulate`）表示"够不到"；
- 此时松开**不释放**，只飘字提示。

**释放时机**：`instant` / `point` 在**松开按键**时结算；若松开时超距，则取消并飘字。

## 13. 数据表格式与内容

数据表用 **TSV**（Tab 分隔）。**解析规则**：

- 首行为表头；`#` 开头的行为注释；空行跳过。
- **空字段 = 两个连续 Tab**，解析后为空字符串；**禁止**用 `-` / `""` / `—` 之类占位。
- **每行列数必须等于表头列数**，否则该行报错并跳过（不要静默容错）。
- `effects` / `augment_effects` 列格式：`k=v;k2=v1,v2`。
- `attrs` / `derived` 列格式：`k=v,k2=v2`。

## 16. 可测试性要求

1. **随机可种子化**：所有随机走 `Rng`（autoload），支持 `Rng.seed_with(n)`；
   **禁止**直接调用全局 `randf()` / `randi()` / `randomize()`。
2. **帧循环显式传参**：系统更新函数签名为 `tick(dt: float)`，
   测试可 `for i in 60*60*30: tick(1.0/60.0)` **快进整局 30 分钟**。
3. **状态可隔离**：`GameState` 与 `StatService` 是 `RefCounted`，可单独 `new()` 出来测试。
4. **提供 5 个 headless 自检脚本**（放 `tests/`）：

| 脚本 | 验证内容 |
|---|---|
| `test_formula.gd` | §3.2 全部公式；评级 S/A/B/C/F 边界 |
| `test_pipeline.gd` | §6.3 管线顺序；减免上限 90%；无敌期不结算；反伤不连锁 |
| `test_repository.gd` | 技能总数 72；cast_mode 分布；subtype 派生正确；非法行被拒绝 |
| `test_inventory.gd` | 7 种拖放；增益查重；仓库满留地上；升级与融合 |
| `test_playtest.gd` | 快进整局：刷怪→击杀→掉落→拾取→升级→商人→祭坛→死亡→结算 |

运行方式：

```
<godot> --headless --path . --script res://tests/test_formula.gd
```

> 测试脚本**不得硬编码绝对路径**（用 `user://` 或直接打印到 stdout）。

## 17. 刻意保留的行为（**不要"顺手修复"**）

以下是**有意设定**，改动即视为不符要求：

1. **召唤物免疫伤害** —— 召唤物不参与伤害结算，只会因寿命到期消失。
2. **`banish` 与 `prison` 原语可无技能使用** —— 属效果原语库的能力预留，
   **不要删除**，也**不要**为它们额外造技能（`banish` 有技能用，`prison` 目前没有）。
3. **无音频、无存档、无多英雄**（英雄只有「极锋」）。
4. **`orange` 品质倍率 = 1.0** —— 与其它品质不成序列，按表实现。
5. **多个技能共用同一图标 key**（如 `ice_nova` 与 `frost_nova` 同为 `skill/05`）—— 按表实现。
6. **`skill/04` 无技能引用** —— 但仍需可生成，保持 key 连续。

## 18. 常见实现陷阱

| 现象 | 原因 | 处理 |
|---|---|---|
| 编译报缩进错误 | `.gd` 用了空格缩进 | 全部改 Tab（§1.2） |
| 技能全失效 / 数值为 0 | TSV 列数错位，或空字段被填了占位符 | 空字段 = 两个连续 Tab；列数 = 21（§13） |
| 联动 / 毁灭者印记不生效 | 没实现 `subtype` 派生 | 见 §4.3 |
| 融合无效果 | 增益技能 `augment_effects` 为空时没回退到自身 `effects` | 见 §4.6 |
| 属性 tooltip 与实际不符 | 自己又算了一遍公式 | 一律调 `Formula`（§3.2） |
| 光环不生效 | 装槽/卸下/拾取后没触发重算 | 用脏标记重算（§2.2） |
| 预览遮罩在冷却时仍显示 | 漏了"CD 中/能量不足只飘字" | 见 §12.4 |
| 角色/图标视觉偏小 | 生成尺寸不符合契约 | 见 §11.2 |
| HUD 位置错乱 | 用了 anchors 自适应而非固定 offset | 见 §12.1 |
| 商人/祭坛用不了 | 交互没过滤"只有玩家" | 判定 `body is Player`（§8.5） |
| 死亡后仍被秒杀 | 无敌期没在伤害入口拦截 | 见 §6.3 步骤 5 |
| 威胁等级只影响新怪 | 忘了对在场敌人做增量缩放 | 见 §8.3 |
| 反伤无限循环 | 反伤又触发了反伤 | 见 §6.3 步骤 7 |
| 引导技能伤害差好几倍 | 把 `duration` 当成了总伤害 | 见 §6.2.1（damage 是**每次**结算量） |
| HUD 一改分辨率就散 | 用了 anchors 自适应 | 用固定 `position`/`size`（§12.0） |
| 技能预览遮罩跟手不对 | 没区分"锁玩家"与"跟鼠标" | 见 §12.4.1 |
| 敌人看不出被控制了 | 没做状态调制色 | 见 §12.5.2 |
| 小地图比例不对 | 缩放算错 | `min(140/6000, 100/4200)`（§12.5） |
| headless 测试结果每次不同 | 用了全局随机 | 走 `Rng`（§16） |
