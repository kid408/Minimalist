## 1. 工作纪律（这 4 条决定成败）

根据以往经验，**绝大多数失败不来自"不会写"，而来自这 4 件事**：

| # | 纪律 | 具体要求 |
|---|---|---|
| **D1** | **一次只写一个文件** | 生成完立刻写入磁盘，**不要**在一条回复里连续输出 5 个以上文件（长输出会被截断，截断后代码残缺且不易发现） |
| **D2** | **长文件分段写** | 单文件接近 **400 行**时必须拆分（规格书 §2.3 红线 3）。拆分不是砍功能，是按职责分成多个文件 |
| **D3** | **每阶段都能启动** | 任何阶段结束时 `godot --headless --path . --quit` 都必须**零报错**。禁止"攒到最后一起调" |
| **D4** | **入口检查没过不许前进** | 每阶段末尾有一组可执行的验证命令。全部通过才进入下一阶段 |

**另外**：所有 `.gd` 用 **Tab** 缩进（Godot 不允许 Tab/空格混用）；
所有文件 UTF-8 无 BOM。

## 6. 高频错误（**开工前先看一遍，能省很多时间**）

| 错误 | 后果 | 怎么避免 |
|---|---|---|
| 一次输出多个文件导致**截断** | 代码残缺，报错难定位 | 纪律 D1：一次一个文件 |
| 单文件超过 400 行 | 输出被截 + 违反架构红线 | 纪律 D2：按职责拆分 |
| 攒到最后才编译 | 几十个错误一起爆，无从下手 | 纪律 D3：每阶段都能启动 |
| `.gd` 用了空格缩进 | Godot 直接编译失败 | 全部用 Tab |
| TSV 空字段填了 `-` / `""` | 被当成真实数值 | 空字段 = 两个连续 Tab |
| 把 `duration` 当成总伤害 | 引导技能伤害差 5 倍 | §6.2.1：damage 是**每次**结算量 |
| 忘了 subtype 派生 | 联动与毁灭者印记全部失效 | §4.3 |
| 光环换槽后不重算 | 被动不生效 | 脏标记重算 |
| 用了全局 `randomize()` | 测试结果不可复现 | 一律走 `Rng` |
| HUD 用 anchors 自适应 | 布局漂移 | 固定 `position`/`size` |
| 反伤又触发反伤 | 无限循环 | 反伤包标记 `no_reflect` |
| 属性 tooltip 自己算一遍 | 数值漂移 | 一律调 `Formula` |
| 想"顺手修好"召唤物免疫 | 违反刻意设定 | 见规格书 §17（6 条不要改） |
